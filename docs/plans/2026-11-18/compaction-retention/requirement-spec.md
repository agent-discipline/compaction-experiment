## 1. 목표·대상 (필수)

새 저장소 `compaction-experiment`에 과제·실행기·채점기를 만들고, 같은 구현 과제를 조건 3가지 × 모델 2종으로 반복 실행해, 컴팩트 전에 대화로 준 결정·제약이 최종 코드에서 지켜졌는지를 조건별 표로 낸다.

- **과제**: 좌석 예약 서비스를 빈 골격 프로젝트에서 시작해 9단계로 구현한다. 단계마다 사용자 메시지 하나가 그 단계의 결정을 전달한다(결정 요약문 — 원본 ADR에서 메인이 구현 결정만 추려 새로 쓴다). 성능 실험·부하 측정은 하지 않는다.

| 단계 | 원본 | 전달하는 결정 |
|---|---|---|
| S0 | ADR-000 | 도메인·테이블 5개·선점과 확정 API·오류 코드·TTL 5분·1인 2매·만료 배치 10초·판정 순서 |
| S1 | ADR-002 | 일반 인덱스 5개(이름 지정), 커넥션 풀 10, **유니크 금지(지속 결정 — 따로 정하기 전까지 어느 단계에서도)** |
| S2 | ADR-003 | 같은 좌석 동시 선점 = 대기 없는 비관적 락, 진 쪽은 409 |
| S3 | ADR-005 | 1인 2매 = 어드바이저리 락 시도 방식 |
| S4 | ADR-006·008 | **번복** — 매수 제어를 한 문장 upsert + 사전 확인으로 바꿈, 쿼터 테이블 도입, 기존 데이터 백필 |
| S5 | ADR-009 | 판매 마감(회차 시작 시각 이후 선점 거절), 판정 순서 마감→좌석→매수, 만료 감소의 가드와 그 자리 복구, 마감 회차의 쿼터 행 정리 |
| S6 | ADR-015 | 확정을 조건부 문장(영향 행 수로 판정)으로, 확정 좌석 부분 유니크 인덱스(유니크 금지의 유일한 예외), 조건부 만료 배치, 경합에서 진 쪽 404 |
| S7 | ADR-016 | **번복** — 확정 기본을 연장 방식으로, 결제 시작 API와 payBy(611초·1초·1초) |
| S8 | — | 마무리: 전체 테스트 통과, 지금까지의 결정을 모두 만족하는지 점검하고 고칠 것 고치기 |

  ADR-012(코드량이 과제 전체의 절반)·014(기본값 불변)·017(결정 미정)과 측정이 본체인 ADR은 뺀다.
- **대화에만 있는 제약**: 첫 턴에 한 번만 말하고 어느 파일에도 적지 않는다. 기계로 확인할 수 있는 것만 고른다(후보: 최상위 패키지 이름 · 이미 적용된 마이그레이션 파일은 고치지 않고 새 버전만 추가 · 금지 의존성 · 테스트 이름 규칙 · 단계마다 커밋하고 메시지 접두 형식 · 응답은 한국어). 개수와 문구는 task 01에서 확정한다.
- **조건**: ①대조군(컴팩트 없음 — 기준값을 올려 과제 끝까지 컴팩트가 일어나지 않게) ②기본 자동 컴팩트(기준값 10만) ③자동 컴팩트 + 아웃박스(사용자 메시지를 발생 시점에 파일에 쌓고, 컴팩트 뒤 SessionStart `compact` 훅이 최근 사용자 메시지 원문과 고정 규칙을 주입).
- **모델**: `claude-opus-5-5`, `claude-sonnet-5-5`.
- **역할**: 메인 = 실험 통제(명세·합의, 과제 요약문과 제약의 확정, 진행자 브리핑, 파일럿 뒤 승인, 결과 보고). 진행자(Fable 5.2 에이전트) = 실행과 채점. 구현·테스트 설계·리뷰 = Opus 워커.

## 2. 경계·불변식 (필수)

- **조건 간에 달라지는 것은 컴팩트 처리뿐이다.** 같은 골격 프로젝트, 같은 사용자 메시지(문자 단위로 동일), 같은 도구 표면, 같은 모델 설정. 조건을 구분하는 것은 기준값 환경 변수와 훅 설정 파일뿐이고, 실행 기록에 해시와 함께 남긴다.
- **결정과 제약은 대화로만 들어간다.** 작업 폴더에 원본 ADR·요약문·제약 목록·채점 자료를 두지 않는다. 에이전트가 원본 프로젝트나 이 저장소의 과제 폴더를 읽지 못하게 막고, 읽으려 한 흔적(도구 입력의 경로)이 있으면 그 실행은 무효다.
- **아웃박스 조건은 실제 하네스가 쓸 수 있는 정보만 쓴다.** UserPromptSubmit 훅이 받은 메시지를 파일에 덧붙이고, 주입 훅은 그 파일만 읽는다. 과제 파일을 직접 읽어 주입하지 않는다. 주입량(최근 메시지 수·메시지당 길이 상한)은 파일럿 전에 고정하고 주입 토큰을 측정값으로 남긴다.
- **컴팩트 여부를 기록으로 확인한다.** 세션 기록의 `compact_boundary`(횟수·`trigger`·전후 토큰·몇 번째 단계 뒤인지)를 실행마다 수집한다. 대조군에 경계가 있거나 컴팩트 조건에 경계가 없으면 무효다. 무효 실행을 조용히 빼지 않고 수를 표에 적는다.
- **채점은 최종 코드와 세션 기록에 대해 기계로 한다.** 모델이 채점하는 항목은 두지 않는다.
  - 숨긴 계약 테스트: 단계별 결정을 HTTP API와 DB 상태로 확인하는 테스트. 에이전트에게 보이지 않고, 실행이 끝난 뒤 최종 코드에 덮어 돌린다.
  - 정적 표지: 설정 값, 마이그레이션 파일(이름·인덱스·제약), 금지 의존성, 패키지 이름, 커밋 메시지 형식, 이미 적용된 마이그레이션의 수정 여부(커밋 이력).
  - 응답 언어: 어시스턴트 발화에서 코드 블록·인용을 뺀 본문의 한글 비율(턴별).
  - 번복 처리: S4·S7 뒤의 최종 상태가 **새 결정**을 따르는지(옛 결정으로 되돌아갔는지).
- **모든 채점 항목에 "결정이 전달된 단계"와 "그 뒤 첫 컴팩트까지의 거리"를 붙인다.** 주 측정값은 "컴팩트보다 앞서 전달된 결정·제약의 위반율"이고, 조건 ①과의 차이로 읽는다.
- **대조군이 기준이다.** 대조군에서도 자주 틀리는 항목은 과제나 채점의 결함이므로 파일럿 뒤에 고치고, 고친 뒤 과제·채점을 동결한다. 동결 뒤에 바꾸면 전 조건을 다시 실행한다.
- 실패·무효·중단 실행을 결과에서 지우지 않는다. 측정값은 실행마다, 단계마다 파일로 저장한다.
- 실행은 한 번에 하나씩 한다(Docker·Testcontainers 자원 경합 방지). need-harness-lab의 유료 실행이 도는 동안에는 돌리지 않는다.
- 공개 저장소에 원본 프로젝트의 문서 원문·사설 IP·홈 경로·대화 인용을 넣지 않는다. 요약문은 새로 쓴 글이고 패키지 이름도 새로 정한다.

## 3. 기준소스 (필수)

- 과제의 결정 내용: 원본 `seat-reservation-lab/docs/adr/ADR-000·002·003·005·006·008·009·015·016`의 결정 절과 설계 절(읽기만). 요약문이 원본과 다르면 요약문이 과제의 정본이다(실험은 원본 재현이 아니라 "전달한 결정이 지켜지는가"를 잰다).
- Claude Code 동작: §0의 사전 시험과 공식 문서의 훅 계약. 다르면 사전 시험을 따르고 차이를 기록한다.
- 실행기 선례: `graph-nav-experiment/scripts/run_experiment.py`(임시 HOME·거부 규칙·감사·재개), `prompt-language-experiment/tools/measure_tokens.py`(입력 고정).

## 4. 금지영역 (필수)

- 원본 `seat-reservation-lab`·하네스 저장소·`~/.claude` 설정과 훅을 바꾸지 않는다. 실험용 훅은 실행 폴더의 설정으로만 건다.
- 실제 세션 기록의 원문과 개인 정보를 이 저장소에 넣지 않는다.
- 본 실행은 파일럿 결과를 사용자에게 보고하고 규모를 승인받은 뒤에 시작한다. push·저장소 공개도 사용자 확인 뒤.
- 에이전트 실행에 호스트의 프로젝트 폴더·자격 증명이 보이지 않게 한다(임시 HOME, 프로젝트 경로 읽기·쓰기 거부, 웹 도구 거부).

## 5. 검증 방법 (필수)

- 도구: 채점기 단위 테스트(분리된 테스트 설계 — 한글 비율, 경계 수집, 무효 판정, 정적 표지), 숨긴 테스트가 과제 요약문과 일치하는지의 리뷰.
- 스모크(유료, 최소): Haiku로 S0~S1만 한 번 돌려 실행기·훅·수집·채점이 끝까지 도는지 확인.
- 파일럿(유료): Sonnet으로 조건 3개를 1회씩, 과제 전체. 확인할 것 — ①대조군이 과제를 끝내고 숨긴 테스트를 대부분 통과하는가 ②컴팩트 조건에서 컴팩트가 몇 번, 어느 단계 뒤에 일어나는가 ③대조군이 정말 컴팩트 없이 끝나는가(맥락 크기) ④아웃박스 주입이 실제로 들어갔는가 ⑤실행당 토큰과 시간 ⑥채점 항목 중 대조군에서 틀리는 것(과제 결함). 결과와 본 실행 규모안을 사용자에게 보고.
- 본 실행 뒤: 조건·모델별 위반율 표(결정 종류·전달 단계별), 반복 간 폭, 무효 수, 결과가 특정 단계 하나에 쏠리는지.

## 6. stakes (필수)

중간. 새 저장소의 측정 도구라 되돌리기 쉽지만, 결과가 하네스 정책(아웃박스 도입)의 근거가 된다. 듀얼 1패스 리뷰(Opus 워커 ∥ codex)와 분리된 테스트 설계를 한다. 에이전트를 호스트에서 넓은 권한으로 돌리므로 격리 설정은 스모크에서 먼저 확인한다.

## 7. 자율성

auto. 파일럿 뒤 보고·승인과 공개 전 확인은 그대로.

## 8. load-bearing 가정

1. 대조군(컴팩트 없음)이 과제를 끝까지 구현하고 숨긴 테스트를 대부분 통과한다. 그렇지 않으면 컴팩트의 영향과 과제 난이도를 구분할 수 없다 → 파일럿 ①. 안 되면 단계를 줄인다.
2. 기준값 10만에서 과제 진행 중 자동 컴팩트가 2회 이상 일어나고, 대조군은 모델의 맥락 한도 안에서 컴팩트 없이 끝난다 → 파일럿 ②③. 대조군이 한도에 닿으면 대조군의 정의를 "기준값을 최대로 올린 조건"으로 바꾸고 그 사실을 결과에 적는다.
