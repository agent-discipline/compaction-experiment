S6 단계입니다. 확정 경로에 구멍이 있습니다. 지금 확정은 "홀드·좌석을 읽고 → 메모리에서 비교하고 → 저장"이라, 확인과 저장 사이에 홀드가 만료되고 배치가 좌석을 풀고 다른 사람이 그 좌석을 잡으면 남의 좌석을 `RESERVED`로 덮을 수 있습니다. 같은 홀드로 확정이 두 번 동시에 오면 같은 좌석 `CONFIRMED`가 두 건 생길 수도 있습니다. 확정을 이렇게 바꿔 주세요.

## 1. 조건부 문장 확정 — 전환 문장의 WHERE가 곧 확인

확정 트랜잭션 하나에서, 확정 처리마다 한 번 정한 기준 시각 `:now`(바인드 값)로 이 순서로:

```sql
-- C1 홀드 소비 = 확인(내 것 · 만료 전)
DELETE FROM seat_hold WHERE id = :holdId AND user_id = :userId AND expires_at > :now
RETURNING seat_id, schedule_id;

-- C2 좌석 전환 = 확인(HELD)
UPDATE product_seat SET status = 'RESERVED' WHERE id = :seatId AND status = 'HELD';

-- C3 예약 생성(created_at = :now)
INSERT INTO reservation (schedule_id, seat_id, user_id, payment_uid, status, created_at)
VALUES (:scheduleId, :seatId, :userId, :paymentUid, 'CONFIRMED', :now) RETURNING id;
```

- 판정은 **영향 행 수**로 합니다. 별도의 확인 SELECT를 먼저 하지 않습니다.
- 확정은 이제 S0에서 정한 구조(엔티티를 읽어 좌석 쪽 메서드에서 검사·전이한 뒤 저장)를 쓰지 않고 위 세 문장으로 합니다(만료 배치도 아래 3절대로). 메모리 비교 뒤 저장하는 방식으로 되돌리지 마세요.
- C1이 0행이면 잠금 없는 진단 한 문장(`SELECT user_id, expires_at FROM seat_hold WHERE id = ?`)으로 코드만 고릅니다: 행 없음 → 404 `HOLD_NOT_FOUND` · 남의 것 → 403 `HOLD_NOT_OWNED` · `expires_at <= :now` → 409 `HOLD_EXPIRED`. (내 것이고 살아 있는데 0행인 경우는 생기지 않아야 합니다 — 생기면 ERROR 로그를 남기고 409 `HOLD_EXPIRED`.)
- C2가 0행이면 409 `SEAT_NOT_HELD`(C1도 함께 롤백).
- 홀드 행 → 좌석 행 순으로 잠기게 됩니다. 이 순서를 바꾸지 마세요.
- **경합에서 진 확정은 계약 코드(404·403·409)로 끝나야 합니다. 5xx는 안 됩니다.** 같은 홀드의 동시 확정 두 개 중 늦은 쪽은 C1이 앞 쪽 트랜잭션이 끝나기를 기다린 뒤 0행이 되어 **404 `HOLD_NOT_FOUND`**를 받습니다.
- 확정은 쿼터 행을 건드리지 않습니다(지금처럼).
- 설정: `seat.confirm.mode: conditional`. 지금은 이 값 하나만 지원하고, 다른 값이면 기동이 실패하게 합니다.

## 2. 최후 방어선 — 확정 좌석 부분 유니크 인덱스

유니크는 제가 따로 정하기 전까지 만들지 않기로 했는데, 이제 하나를 정합니다 — 이것 하나만입니다.

```sql
CREATE UNIQUE INDEX uq_reservation_confirmed_seat ON reservation (seat_id) WHERE status = 'CONFIRMED';
```

- 같은 좌석의 `CONFIRMED`는 1건만. `CANCELED` 이력은 막지 않습니다. `IF NOT EXISTS`는 쓰지 마세요(기존 중복이 있으면 마이그레이션이 실패해야 합니다).
- C3가 이 인덱스에 걸리면(SQLSTATE `23505`이고 위반한 제약 이름이 `uq_reservation_confirmed_seat`일 때만) 409 `SEAT_NOT_HELD`로 바꾸고 ERROR 로그를 남깁니다. 다른 무결성 오류는 그대로 올립니다.

## 3. 만료 배치도 조건부로

배치가 낡은 판단으로 확정된 좌석을 `AVAILABLE`로 덮거나, 지우지 못한 홀드만큼 카운터를 내리는 일이 없게 합니다. 배치 한 번 = 트랜잭션 하나는 그대로이고, 배치 처리마다 한 번 정한 기준 시각 `:now`(바인드 값)를 씁니다.

- **조건부 삭제**: 지우는 문장에서 만료를 다시 확인합니다(`DELETE FROM seat_hold WHERE … AND expires_at <= :now`). 그 사이 확정이 가져간 홀드는 0행으로 지나갑니다.
- **지운 행만큼 카운터 감소**: 그 삭제에서 실제로 지운 행 수만큼 쌍별로 내립니다(가드 감소와 그 자리 복구는 지금 규칙 그대로). 복구 값은 삭제가 반영된 상태에서 센 값(남은 홀드 행 수 + `CONFIRMED` 수)이며, 지운 수를 다시 빼지 않습니다.
- **좌석 되돌림**: 실제로 지운 홀드의 좌석만, 좌석이 `HELD`이고 그 좌석에 다른 살아 있는 홀드(`expires_at > :now`)가 없을 때만 `AVAILABLE`로 바꿉니다.

테스트: 같은 홀드로 동시에 두 번 확정하면 하나는 200, 하나는 404 `HOLD_NOT_FOUND`(5xx 0)이고 예약은 1건. 만료된 홀드(배치 전) 확정 → 409 `HOLD_EXPIRED`, 배치가 지운 뒤 → 404 `HOLD_NOT_FOUND`. 같은 좌석에 `CONFIRMED` 두 건을 직접 넣으면 DB가 거절하고 `CANCELED`는 허용. 확정이 먼저 끝난 홀드를 배치가 만나도 좌석은 `RESERVED`, 카운터는 `홀드 + 확정` 그대로, 틱은 롤백되지 않고 반영. 테스트는 통과시켜 주세요.
