S5 단계입니다. 세 가지를 넣습니다: 판매 마감, 카운터가 어긋났을 때 만료 배치가 멈추지 않게 하기, 마감 회차의 쿼터 행 정리.

## 1. 판매 마감

- 회차의 `starts_at`은 지금 저장만 되고 아무 데서도 검사하지 않습니다. **현재 시각이 `starts_at` 이상이면**(시작 정각에는 이미 마감) 선점을 거절합니다: **409 `SCHEDULE_CLOSED`**(새 에러 코드, 실패 본문 형식은 기존과 같습니다).
- 판정은 선점 트랜잭션 안의 **첫 단계**입니다. 회차 행을 공유 락으로 읽습니다: `SELECT starts_at FROM product_schedule WHERE id = ? FOR SHARE`. 회차가 없으면 404 `SEAT_NOT_FOUND`.
- 선점의 판정 순서는 이제 **마감 → 좌석 → 매수**입니다. 마감 판정이 좌석 선조회와 카운터 upsert보다 앞서야 하므로, 마감된 회차에서는 쿼터 행이 생기거나 올라가지 않습니다.
- **확정은 막지 않습니다.** 마감 전에 잡은 홀드는 마감 뒤에도 확정할 수 있습니다.

## 2. 만료 감소를 쌍 단위로 견디게 (S4의 감소 방식을 바꿉니다)

지금은 쿼터 행이 없거나 `cnt`가 지울 수보다 작으면 감소가 실패하고, 만료 배치 트랜잭션 전체가 롤백되어 매 틱 반복됩니다 — 어긋난 쌍 하나 때문에 모든 회차의 만료가 멈춥니다. 이렇게 바꿔 주세요.

- 만료 배치는 지운 홀드를 (회차, 사용자) 쌍으로 묶고, **쌍을 (schedule_id, user_id) 오름차순으로** 처리합니다.
- 쌍마다 가드 감소: `UPDATE user_hold_quota SET cnt = cnt - ? WHERE schedule_id = ? AND user_id = ? AND cnt >= ?`(두 `?` 모두 그 쌍에서 지우는 홀드 수 n).
- 영향 행이 0이면(행 없음 또는 `cnt < n`) **그 쌍만 그 자리에서 실제 값으로 복구**합니다(감소 대신 덮어쓰기). 실제 값 = 그 쌍의 `seat_hold` 행 수(이번 틱에 지우는 홀드는 빼고) + `CONFIRMED` 예약 수. 순서: 쿼터 행을 `FOR UPDATE`로 잠그고(없으면 `cnt = 0`으로 만든 뒤 잠그고) → 그다음 새 문장으로 실제 값을 세어 → `cnt`를 그 값으로 덮어씁니다. 같은 만료 트랜잭션 안에서 합니다. 나머지 쌍의 만료는 그대로 진행되어야 합니다.
- 복구가 일어난 쌍은 WARN 로그로 남깁니다.
- 가드로 못 잡는 어긋남(`cnt`가 실제보다 조금 작거나 큰데 감소는 성공하는 경우)은 이번 범위가 아닙니다. 주기적으로 전체를 대조하는 스케줄러도 만들지 않습니다.

## 3. 마감 회차의 쿼터 행 정리

쿼터 행은 만료로 지워지지 않아 계속 쌓입니다. 마감된 회차의 쿼터 행을 지우는 스케줄 작업을 둡니다.

- 주기마다: `starts_at <= 지금`이고 쿼터 행이 남아 있는 회차를 id 순으로 고릅니다.
- 회차 하나 = 트랜잭션 하나: ① `SELECT starts_at FROM product_schedule WHERE id = ? FOR UPDATE`(선점의 `FOR SHARE`와 직렬화됩니다) → 잠근 뒤 다시 보니 마감이 아니면 건너뜀 ② 새 문장으로 그 회차에 `seat_hold` 행이 있는지 확인 ③ **홀드가 하나도 없을 때만** `DELETE FROM user_hold_quota WHERE schedule_id = ?`(확정 쌍의 행까지 전부). 홀드가 남아 있으면 지우지 않고 다음 주기에 다시 봅니다.
- 한 회차의 실패가 다른 회차의 정리를 막지 않게 하고, 실패는 ERROR 로그로 남깁니다.
- 설정: `seat.hold.counter-drift.cleanup.mode: schedule`(지금은 이 값 하나만 지원합니다), `seat.hold.counter-drift.cleanup.interval: 60s`.

테스트: 마감 회차 선점 → 409 `SCHEDULE_CLOSED`(좌석이 이미 `HELD`이거나 사용자가 매수를 다 채웠어도 `SCHEDULE_CLOSED`가 먼저), 마감 회차의 기존 홀드 확정 → 200. 쿼터 행을 지우거나 `cnt`를 0으로 만든 쌍이 있어도 만료 틱이 롤백되지 않고 반영되고 다른 사용자의 만료도 처리되며 그 쌍의 `cnt`가 실제 값이 되는지. 정리가 홀드가 남은 마감 회차는 건드리지 않고, 홀드가 없는 마감 회차의 쿼터 행은 지우는지. 테스트는 통과시켜 주세요.
